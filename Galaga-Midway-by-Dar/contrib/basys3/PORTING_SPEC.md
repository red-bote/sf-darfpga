# Galaga DE10-lite → Basys3 porting spec

This spec summarizes the step-by-step process of porting Dar's Galaga hardware to the
Digilent Basys 3, mirroring the generic reference spec (`PORTING_SPEC.md`) and the Pooyan /
Time-Pilot per-machine specs.

Galaga **is scripted**: `Makefile` + `contrib/{tools,basys3/{tools,vivado}}` are present and
`make setup`, `make create_prj`, and `make clk_wiz` run end-to-end against the pristine Dar
source tree (`vhdl_galaga_rev_0_3_2018_05_06/`, fetched locally, not checked in). The
top-level wrapper `galaga_basys3.vhd` and its generator
`make_de10_lite_to_basys3_patch.sh` are authored from the sources of truth below (this doc —
including the scan doubler wiring in §12 — the machine `README.md`, and the pristine source
tree).

- Source archive: `vhdl_galaga_rev_0_3_2018_05_06.zip` (SourceForge folder `galaga`, per
  the repo-root `downloads.md`) → `vhdl_galaga_rev_0_3_2018_05_06/` at the machine root.
- Top entity: `galaga_basys3` (target file `sources_1/new/galaga_basys3.vhd`)
- Part: `xc7a35tcpg236-1`, VHDL target language

## 2. Clocking

- `clk_wiz_0` MMCM (100 MHz in) produces a single **36 MHz** `clk_out1` (verified, machine
  README; generated and confirmed via `make clk_wiz`). Solved MMCM constants:
  `DIVCLK_DIVIDE=5`, `CLKFBOUT_MULT_F=49.5`, `CLKOUT0_DIVIDE_F=27.5`; reset active-high (btnC),
  `locked` used.
- The pristine DE10-lite top drives the `galaga` core from `clock_18` (18 MHz, from its own
  `max10_pll_18M_11M`), and derives a `clock_9` (18 MHz ÷ 2, toggle-on-`clock_18` pattern) to
  clock the PS/2 keyboard/joystick logic. On Basys 3, `clock_36` ÷ 2 supplies `clock_18` for the
  core in the same role; `clock_9` is derived from `clock_18` the same way (halving pattern
  carried over unchanged).
- The scan doubler needs `clock_12`/`clock_6` (§5), which do **not** come from the core-clock
  halving chain above — they are generated by a separate mod-6 counter clocked directly from
  `clock_36`, per §12: `clock_6` is a 6 MHz 50%-duty square wave
  (toggles on slot states 1 and 4 of a 0–5 counter), `clock_12` is a 12 MHz-rate pulse train
  (not a square wave, asserted briefly at slot states 1 and 4). That section also records that
  wiring `clock_18` or `clock_36` directly to the doubler's `clk_sys` did not work, hence the
  dedicated counter.

## 3. Reset polarity

- **Basys 3:** `reset <= btnC` (active-high button), mirroring Pooyan.
- **DE10-lite (confirmed):** `reset <= not reset_n`, `reset_n` aliased to `key(0)` — active-low
  key, inverted on the DE10 top itself.

## 4. Core instantiation

- Confirmed `galaga` entity (`rtl_dar/galaga.vhd`, post-patch — see §8 `galaga_vga_sync.patch`):
  `clock_18`, `reset` in; `video_r(2:0)`, `video_g(2:0)`, `video_b(1:0)`, `video_clk`,
  `video_csync`, `video_blankn`, `video_hs`, `video_vs` out; `audio(9:0)` out; inputs `b_test`,
  `b_svce` (both tied `'1'` on the DE10 top — no dip-switch ports exist on this core), `coin`,
  `start1/2`, `left1/2`, `right1/2`, `fire1/2`.
- `video_hs`/`video_vs` are present as ports only after `galaga_vga_sync.patch` is applied (see
  §8) — the pristine core leaves them commented out, with the video generator's internal
  `hsync`/`vsync` wired to `open`.
- Keep the port map unchanged aside from wiring the now-exposed `video_hs`/`video_vs` into the
  scan doubler (§5).

## 5. Video / scan doubler (31 kHz VGA)

- Galaga uses an imported **MiST `scandoubler.v`** (`imports/mist/scandoubler.v`), sourced from
  Arcade_Galaga — **not** the DECA `vga_scandoubler.v` used by Pooyan/Time-Pilot (verified,
  machine README). This divergence is expected for Galaga.
- The full wiring — component declaration, port map, `blankn`-gated 3/3/2→6-bit RGB padding via
  MSB replication, 6-bit→4-bit output narrowing (top 4 of 6 bits kept), and direct (uninverted)
  `hs_in`/`vs_in` from the core's `video_hs`/`video_vs` — is specified in §12, treated as the
  authoritative target for this redo. Clock inputs
  (`clk_sys`=`clock_12`, `ce_x1`=`clock_6`, `ce_x2`='1', `scanlines`="00") per §2 above.
- **Display-mode switch** via `sw(13)` in `galaga_basys3.vhd` (active, not commented):
  - `sw(13)=0` (default): 31 kHz VGA — the scan-doubled 6-bit RGB narrowed to 4 bits, `hsync_o`/`vsync_o`.
  - `sw(13)=1`: 15 kHz TV — native core RGB padded to 4 bits (`r&'0'`, `g&'0'`, `b&"00"`, blanked on
    `blankn`), `vga_hs <= csync`, `vga_vs <= '1'`. Requires a 15 kHz RGB monitor or an RGB→composite/component
    converter; a standard VGA LCD will not sync. The scandoubler and mod-6 counter keep running in this mode
    (not clock-gated). See §12.6.

## 6. Audio (mono PWM on PmodAMP2)

- Mono PWM audio on PmodAMP2 (verified, machine README).
- Documented switch semantics (verified, machine README):
  - `sw(15)` → `O_PMODAMP2_GAIN`: gain 0 = 12 dB, 1 = 6 dB
  - `sw(14)` → `O_PMODAMP2_SHUTD`: shutdown 0 = off, 1 = on

## 7. Inputs

- PS/2 keyboard on JB (`ps2_dat`/`ps2_clk`) OR-merged with the JA joystick (verified, machine
  README). Key map (verified, with scancodes): Left `←` 0x6B, Right `→` 0x74, Fire Space 0x29,
  Coin F3 0x04, Start 1 F1 0x05, Start 2 F2 0x06.
- JA joystick, active-low (switch to GND): `JA1=Right, JA2=Left, JA3=Down, JA4=Up, JA7=Fire`.
  Invert (`not JA`) to active-high to match the core boundary (Pooyan pattern).
- Coin/start from joystick via combos: `coin = fire+up`, `start1 = fire+left`.
- P2 mirrors P1 left/right/fire inputs (verified, machine README).
- `btnC` = reset.
- **Known issue** (verified, machine README): the keyboard can randomly stick to the right (and
  maybe left) — an original core issue.

## 8. Patches (all applied by `make setup` / `make create_prj`, none manual-only)

Four patches exist under `contrib/code/`; `setup_galaga.sh` applies all of them to the pristine
tree except the two excluded by name (see below), each idempotently (`patch -p1 --forward`):

- **`galaga_bgpalette_xor_length_fix.patch`** — synthesis-shape fix, `rtl_dar/galaga.vhd`
  (`bgpalette_addr`, around line 521). The pristine expression XORs `hcnt(1 downto 0)` against
  `flip_h & flip_h` *after* prefixing a `'1'`/`'0'` bit, i.e. the xor's left operand is 3 bits
  wide from the concatenation associating before the xor; this mismatches the 2-bit right
  operand's width. The fix parenthesizes `(hcnt(1 downto 0)) xor (flip_h & flip_h)` first (both
  2-bit) and concatenates the `'1'`/`'0'` prefix onto the result. Applied automatically by
  `setup_galaga.sh`; verify with
  `grep -n 'xor (flip_h & flip_h))))' vhdl_galaga_rev_0_3_2018_05_06/rtl_dar/galaga.vhd`.
- **`galaga_credit_mode_fix.patch`** — gameplay bug fix (not synthesis): Start 1 / Start 2 are
  ignored after inserting a coin on the pristine core; re-enables the Namco 51XX credit-mode
  flag (`cs51XX_credit_mode <= '1'`) on every hardware coin edge, at `rtl_dar/galaga.vhd:848`.
  Applied automatically by `setup_galaga.sh`; verify with
  `grep -n "cs51XX_credit_mode <= '1'" vhdl_galaga_rev_0_3_2018_05_06/rtl_dar/galaga.vhd`. See
  `contrib/code/51xx_credit_state_machine_investigation.md` for the still-open investigation
  into the underlying 51XX state machine this patch works around.
- **`galaga_vga_sync.patch`** — synthesis-fix/enabling patch, `rtl_dar/galaga.vhd`: the pristine
  core leaves `video_hs`/`video_vs` commented out of the entity port list, with the video
  generator's `hsync`/`vsync` wired to `open`. Uncomments the two ports and wires them to
  `hsync`/`vsync`, exposing the sync signals the scan doubler needs (§5). Applied automatically
  by `setup_galaga.sh`; verify with
  `grep -n "hsync   => video_hs" vhdl_galaga_rev_0_3_2018_05_06/rtl_dar/galaga.vhd`.
- **`scandoubler_fix.patch`** — Vivado 2020.2 Verilog-2001 parser fix, *not* applied to the
  pristine tree by `setup_galaga.sh` (excluded by the `*scandoubler_fix.patch` name-glob).
  Vivado 2020.2 rejects the single-value unpacked array size
  `sd_buffer[2*2**HCNT_WIDTH]` in the imported MiST `scandoubler.v` (Synth 8-2671: implicit
  lower bound not accepted); rewritten to the explicit range `[0:2*2**HCNT_WIDTH-1]`. Applied by
  `create_project.sh` (§10) only to the copied instance at
  `galaga_basys3.srcs/sources_1/imports/mist/scandoubler.v` — the canonical import at
  `contrib/code/scandoubler.v` stays pristine and is never modified, per the cleanroom-import
  rule.

**Layout divergence (flagged as-is):** the four fix patches live at `contrib/code/` (flat), not
under `contrib/basys3/code/` as in the Pooyan/Time-Pilot convention. This is an open item; no
migration is prescribed here. Note the generated `galaga_de10_lite_to_basys3.patch` *is* written
to `contrib/basys3/code/` (the conventional location), matching Pooyan/Time-Pilot.

## 12. Scan doubler wiring (31 kHz VGA)

This section is self-contained; it does not depend on any other section or document. It
specifies how the `scandoubler` component (from
`basys3/galaga_basys3.srcs/sources_1/imports/mist/scandoubler.v`) is instantiated and wired into
the Basys 3 top level (`basys3/galaga_basys3.srcs/sources_1/new/galaga_basys3.vhd`, instance
label `scandoubler_inst`). It covers the component declaration, every port connection, the
signals on each side of the instance, and the upstream/downstream logic those signals connect
to, including the derivation of the two clock signals (`clock_12`, `clock_6`) that drive the
instance.

### 12.1 Component declaration (as declared in `galaga_basys3.vhd`)

```vhdl
component scandoubler
    port (
        clk_sys   : in  std_logic;
        scanlines : in  std_logic_vector (1 downto 0);
        ce_x1     : in  std_logic;
        ce_x2     : in  std_logic;
        hs_in     : in  std_logic;
        vs_in     : in  std_logic;
        r_in      : in  std_logic_vector (5 downto 0);
        g_in      : in  std_logic_vector (5 downto 0);
        b_in      : in  std_logic_vector (5 downto 0);
        hs_out    : out std_logic;
        vs_out    : out std_logic;
        r_out     : out std_logic_vector (5 downto 0);
        g_out     : out std_logic_vector (5 downto 0);
        b_out     : out std_logic_vector (5 downto 0)
    );
end component;
```

This declaration binds by name to the Verilog module `scandoubler`
(`mist/scandoubler.v`), which parameterizes `COLOR_DEPTH = 6` and
`HCNT_WIDTH = 9` at its defaults; the top level does not override either
parameter, so both take their default values.

|---|---|---|---|
| `clk_sys` | in | `clock_12` | `std_logic` |
| `scanlines` | in | `"00"` (literal) | `std_logic_vector(1 downto 0)` |
| `ce_x1` | in | `clock_6` | `std_logic` |
| `ce_x2` | in | `'1'` (literal) | `std_logic` |
| `hs_in` | in | `hsync` | `std_logic` |
| `vs_in` | in | `vsync` | `std_logic` |
| `r_in` | in | `vga_r_i` | `std_logic_vector(5 downto 0)` |
| `g_in` | in | `vga_g_i` | `std_logic_vector(5 downto 0)` |
| `b_in` | in | `vga_b_i` | `std_logic_vector(5 downto 0)` |
| `hs_out` | out | `hsync_o` | `std_logic` |
| `vs_out` | out | `vsync_o` | `std_logic` |
| `r_out` | out | `vga_r_o` | `std_logic_vector(5 downto 0)` |
| `g_out` | out | `vga_g_o` | `std_logic_vector(5 downto 0)` |
| `b_out` | out | `vga_b_o` | `std_logic_vector(5 downto 0)` |

### 12.3 Upstream signals (into the scan doubler)

#### 12.3.1 `hs_in` / `vs_in`

Driven directly by the `hsync` and `vsync` outputs of the `galaga` core
instance (its `video_hs` / `video_vs` ports), with no intermediate logic.
These are the core's native, undoubled sync signals, generated internally by
the core at a 15.625 kHz horizontal line rate and a 384-count-per-line,
264-line-per-frame counter geometry. The core's `video_csync` output is not
connected to the scan doubler; it drives `vga_hs` directly in the `sw(13)`
TV-mode output path instead (see §12.6).

#### 12.3.2 `r_in` / `g_in` / `b_in`

Driven by intermediate signals `vga_r_i`, `vga_g_i`, `vga_b_i`, each
declared as `std_logic_vector(5 downto 0)`. These are combinationally
assigned, immediately ahead of the instance, from the core's native RGB
output (`r`, `g`, `b`, local copies of `galaga`'s `video_r`/`video_g`/
`video_b` ports, 3/3/2 bits respectively) and the core's `blankn` output:

```vhdl
vga_r_i <= r & r         when blankn = '1' else "000000";
vga_g_i <= g & g         when blankn = '1' else "000000";
vga_b_i <= b & b & b     when blankn = '1' else "000000";
```

Each channel is padded to 6 bits by MSB replication (`r&r` duplicates the
3-bit red field to fill 6 bits, etc.), matching the scan doubler's
`COLOR_DEPTH = 6` default. During the core's blanking window
(`blankn = '0'`) all three channels are forced to `"000000"` regardless of
the core's RGB output value.

#### 12.3.3 `clk_sys`, `ce_x1`, `ce_x2`

`clk_sys` is driven by `clock_12`, and `ce_x1` by `clock_6`. Both are
generated in `galaga_basys3.vhd` by one dedicated mod-6 `slot` counter,
clocked by a 36 MHz clock (`clock_36`, itself produced by the design's MMCM
from the 100 MHz board oscillator):

```vhdl
process (clock_36)
begin
    if rising_edge(clock_36) then
        clock_12 <= '0';
        if slot = "101" then
            slot <= (others => '0');
        else
            slot <= std_logic_vector(unsigned(slot) + 1);
        end if;
        if slot = "100" or slot = "001" then
            clock_6 <= not clock_6;
        end if;
        if slot = "100" or slot = "001" then
            clock_12 <= '1';
        end if;
    end if;
end process;
```

- `slot` counts `"000"` through `"101"` (0-5) and wraps, advancing on every
  `clock_36` edge.
- `clock_6` toggles when `slot = "100"` or `slot = "001"` (states 4 and 1,
  evenly spaced 3 states apart). A full toggle period spans 6 `clock_36`
  cycles, giving `clock_6` a frequency of 36 MHz / 6 = 6 MHz with 50% duty.
- `clock_12` is assigned `'0'` unconditionally at the top of the process,
  then overridden to `'1'` only on the same two `slot` states that toggle
  `clock_6`. This produces a train of single-`clock_36`-cycle-wide high
  pulses recurring every 3 `clock_36` cycles: a 12 MHz *rate* of rising
  edges, but with roughly a 1:3 duty cycle rather than a symmetric 1:2. It is
  not a toggle-based square wave, and it is not routed through a global
  clock buffer or an MMCM; it is a plain registered pulse in fabric logic,
  used directly as the `clk_sys` clock net for `scandoubler_inst`.

A source comment immediately above this process
(`-- clock_18, video_clk i clock_36 no funciona`, Spanish: "does not work")
records that `clock_18` (18 MHz) and `clock_36` (36 MHz) were tried as
`clk_sys` for the scan doubler and did not work; `clock_12` is the value
actually wired to `clk_sys` in the current design.

`ce_x2` is tied to the constant `'1'`, so the scan doubler's output/
re-timing stage is enabled on every `clk_sys` edge with no additional
gating.

#### 12.3.4 `scanlines`

Tied to the constant `"00"`, disabling the scan doubler's built-in scanline
attenuation feature (25/50/75% options exist in the component but are
unused here).

### 12.4 Downstream signals (out of the scan doubler)

#### 12.4.1 `hs_out` / `vs_out`

Captured into `hsync_o` / `vsync_o`, which drive the top-level output ports
`vga_hs` and `vga_vs` directly, with no intermediate logic:

```vhdl
vga_hs <= hsync_o;
vga_vs <= vsync_o;
```

#### 12.4.2 `r_out` / `g_out` / `b_out`

Captured into `vga_r_o`, `vga_g_o`, `vga_b_o` (each `std_logic_vector(5
downto 0)`), then truncated to the top 4 bits of each 6-bit field to drive
the 4-bit-per-channel `vga_r` / `vga_g` / `vga_b` output ports:

```vhdl
vga_r <= vga_r_o (5 downto 2);
vga_g <= vga_g_o (5 downto 2);
vga_b <= vga_b_o (5 downto 2);
```

The two low-order bits of each scan-doubler output channel are discarded.
`vga_r`/`vga_g`/`vga_b` are the entity's board-facing VGA ports, constrained
in `Basys-3-Master.xdc` to the Basys 3's 4-bit-per-channel VGA connector
pins.

### 12.5 Full signal flow diagram

```
galaga core                          galaga_basys3.vhd                         scandoubler_inst              galaga_basys3.vhd            board pins
------------                         ------------------                        -----------------              ------------------            ----------
video_hs   ------------------------> hsync -----------------------------------> hs_in
video_vs   ------------------------> vsync -----------------------------------> vs_in
video_r(2:0), video_g(2:0),
video_b(1:0), video_blankn --------> r, g, b, blankn
                                      vga_r_i <= r&r      (or 0 if !blankn) ---> r_in
                                      vga_g_i <= g&g      (or 0 if !blankn) ---> g_in
                                      vga_b_i <= b&b&b    (or 0 if !blankn) ---> b_in
                                      clock_12 ------------------------------> clk_sys
                                      clock_6 -------------------------------> ce_x1
                                      '1' ------------------------------------> ce_x2
                                      "00" ------------------------------------> scanlines
                                                                                 hs_out ---> hsync_o -------> vga_hs
                                                                                 vs_out ---> vsync_o -------> vga_vs

                                                                                 g_out(5:2) -----------------------------------> vga_g ---> VGA connector G
                                                                                 b_out(5:2) -----------------------------------> vga_b ---> VGA connector B
```

### 12.6 Signals not connected to the scan doubler

- `video_csync` (composite sync) from the `galaga` core: not routed to the
  scan doubler, but used by the **TV mode** display switch in the top level.
- The active `sw(13)` mode switch selects between the scan-doubled VGA path
  (above) and a native 15 kHz TV path that bypasses `scandoubler_inst`:
  - `sw(13)='1'` → `vga_r/r/g/b` from native core RGB padded to 4 bits and
    blanked on `blankn`; `vga_hs <= csync`; `vga_vs <= '1'`.
  - `sw(13)='0'` → the scan-doubled path (`r_out(5:2)`, `hsync_o`, `vsync_o`).
  This mirrors the DE10-lite original's intended-but-commented
  `tv15Khz_mode` design (`vga_hs <= csync when tv15Khz_mode = '1' else hsync`).
